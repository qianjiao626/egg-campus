# 蛋蛋校园资料、任务中心、反馈与 RBAC 重构设计

> 日期：2026-08-26
> 状态：需求已逐项确认，等待用户审阅本文档
> 关联调研：[RBAC 与反馈附件开源方案调研](../../research/2026-08-26-rbac-open-source-options.md)

## 1. 目标与边界

本轮一次性解决以下问题：

1. 开放个人资料二次编辑，并与盲盒资料使用同一份数据。
2. 将“我的打听”和“我的反馈”并入“我的任务”。
3. 修复发布打听后仍出现 `Route GET` 原始错误的问题。
4. 将旧管理员账号迁移为两个受保护的固定管理员，并强制首次改密。
5. 建立可配置、可限时、立即生效、可审计的细粒度 RBAC。
6. 将反馈升级为多轮时间线，并支持受保护的图片附件。

本轮不删除手机号等历史数据库字段，不触碰“航线”项目、Supabase 配置或数据。短信登录与短信 provider 仍保持关闭。

## 2. 已确认的产品规则

### 2.1 个人资料

- 个人资料页右上角增加“编辑资料”，使用统一弹窗编辑。
- 可修改：昵称、邮箱、学校、专业、年级、城市、年龄、简介、MBTI、兴趣、技能标签。
- 不可修改：用户 ID、授权、蛋蛋币、经验、历史统计。手机号不展示。
- 昵称和邮箱必须唯一；昵称每 30 天最多修改一次。
- 修改邮箱后将 `verifiedEmailAt` 清空，但账号仍可使用该邮箱登录。
- 两个固定管理员的昵称永久锁定，其他资料仍可编辑。
- 昵称修改后，历史任务、打听、回复和反馈统一展示新昵称；审计记录保留修改前后值。
- MBTI、兴趣和技能是个人资料与盲盒共同使用的规范数据，任一入口修改后另一处立即同步。
- 保存前后都执行敏感词校验，用户提示不显示具体敏感词。

### 2.2 “我的任务”信息架构

“我的任务”顶部固定四个一级标签：

1. 我发布的
2. 我认领的
3. 我的打听
4. 我的反馈

侧边栏不再单独显示“我的打听”和“我的反馈”。旧页面入口保留内部重定向，防止旧通知或链接失效。

- 每次进入“我的任务”默认打开“我发布的”。
- 四个标签分别显示未读数量，不因进入标签而批量清空。
- 打开具体记录时，只清除该记录的未读状态。
- 发布打听成功后是唯一例外：自动切换到“我的打听”，立即加载刚发布的记录。

### 2.3 打听错误处理

- 修正发布成功后刷新“我的打听”使用的 API 路径和 `/dd/api` 前缀。
- 前端不能直接显示 Fastify 的 `Route GET... not found`、堆栈、SQL、Prisma 或文件路径。
- 服务端返回稳定错误码；前端映射为中文可执行提示。
- 发布成功提示不能被随后一次列表刷新失败覆盖。
- 增加“发布 -> 查询我的打听 -> 打开详情”的路由级集成测试。

## 3. RBAC 设计

### 3.1 开源组件选择

采用：

- `@casl/ability`：服务端动作和资源权限判定。
- `@casl/prisma`：将资源范围规则转成 Prisma 查询条件。

不采用本期 node-casbin Prisma adapter：其当前版本要求 Prisma 7，并带 PostgreSQL 驱动，与现有 Prisma 6 + MySQL 不匹配。OpenFGA、Permify、Ory Keto 和 Cerbos 都会增加独立服务或额外数据库运维，本期不引入。

### 3.2 数据模型

新增规范化模型：

- `Role`：角色名称、说明、状态、系统保护标记。
- `Permission`：稳定的代码权限键和中文说明。
- `RolePermission`：角色勾选的权限集合。
- `UserRoleGrant`：用户角色授权、授予人、开始时间、到期时间、永久标记和撤销状态。
- `RoleGrantAudit`：授予、续期、永久化、撤销和停用的追加式历史。

本期不增加角色继承；用户可以同时拥有多个角色，最终权限取所有有效角色的并集。每个角色授权拥有独立期限。本期只有允许权限，不提供“显式拒绝”。

有效授权必须满足：

- 已到开始时间；
- 未撤销；
- 角色处于启用状态；
- `expiresAt` 为空，或晚于可信服务端当前时间。

### 3.3 请求鉴权

JWT 只证明身份和会话，不作为最终授权依据。每个受保护请求按以下顺序处理：

1. 验证会话和用户状态。
2. 若用户必须修改密码，只允许修改密码和退出。
3. 读取当前有效角色和权限，构建 CASL Ability。
4. API 层检查动作权限，查询层强制加入资源范围条件。
5. 在写事务中再次校验目标保护规则，写业务数据和审计。

角色权限保存、角色停用、授权撤销和期限到达后，下一个请求立即使用新权限。已打开管理页面不形成授权。

### 3.4 固定管理员与首次改密

- 现有旧管理员账号原地重命名为 `蛋总-敦敦`，保留用户 ID 和全部历史关联。
- 新建第二个固定账号 `蛋总-千焦`。
- 两者拥有相同、永久、受保护的完整权限。
- 两者不能被删除、冻结、降级、撤销授权、设置期限或互相修改权限。
- 固定管理员不能修改昵称。
- 系统不允许产生第三个固定超级管理员；其他用户最高只能获得普通或自定义管理角色。
- 两个临时密码不进入源码、迁移文件、Git、文档或 Obsidian。部署时通过隐藏终端输入生成哈希。
- 临时密码首次登录后只能进入设置新密码界面。新密码至少 8 位，且不能与临时密码相同；成功后撤销其他会话。
- 公开界面不显示“根管理员”或“超级管理员”，统一显示“管理员”。

### 3.5 角色与期限管理

两个固定管理员可创建自定义角色并勾选细粒度权限。一个用户可获得多个角色。

快捷期限和选项说明：

- 1 小时：临时审核或短时协助。
- 7 天：短期活动管理。
- 1 个月：月度运营。
- 1 季度：阶段性管理。
- 永久：长期有效，但不能管理权限。
- 自定义：最短 1 小时、最长 1 年。

重复授予同一角色时更新现有授权，不创建重复有效关系；每次变化单独写审计。固定管理员可以续期、改为永久或立即撤销。

自定义角色不物理删除，只能停用归档。停用前显示受影响人数并二次确认；停用后该角色提供的权限立即失效，历史记录保留。

### 3.6 权限管理界面

管理员侧边栏新增“用户与权限”，包含：

- 用户授权：搜索用户、查看角色、授予、续期、永久化和撤销。
- 角色管理：创建角色、填写说明、勾选权限、查看人数、停用归档。
- 权限审计：查看授权和敏感操作记录。

权限按资源和动作拆分，选项后显示说明，高风险权限醒目标记。初始权限目录至少包括：

- 用户：查看列表、查看详情、编辑资料、冻结、恢复。
- 任务：查看、发布、审核、修改、下架、处理认领、处理申诉。
- 打听：查看、隐藏内容、处理退款。
- 反馈：查看、回复、修改状态、标记待修改、查看附件、隐藏附件。
- 盲盒：处理举报；不能任意浏览私聊。
- 蛋蛋币：查看流水、调整余额、处理退款。
- 内容：管理敏感词规则、公告和演示数据。
- 审计：查看和导出审计记录。
- 权限管理：创建角色、编辑角色、授予角色、设置期限和撤销角色。该组仅两个固定管理员拥有，不能授予其他账号。

### 3.7 私聊隐私

管理员不能搜索或浏览全部私聊。只有用户发起聊天举报后，具备“处理聊天举报”权限的管理员才能查看被举报消息及其前后有限上下文。每次读取都写入审计。

## 4. 管理员界面与身份展示

- 有效管理员重新登录时默认进入管理界面。
- 侧边栏提供图标按钮，在管理模式和普通用户模式之间切换。
- 切换只改变界面，不改变后端权限；选择只在当前登录会话中记忆。
- 所有有效管理员在侧边栏、个人名片、任务/打听发布者和管理员列表统一显示“管理员”。
- 管理员拥有专属渐变边框和小图标，小图标使用缓慢光泽扫过。
- 不公开具体自定义角色名称；角色名称仅本人权限详情和管理后台可见。
- 权限到期后标签、边框和图标立即消失。
- 动画支持 `prefers-reduced-motion`，减少动态效果时自动关闭。

## 5. 反馈工单设计

### 5.1 状态与时间线

状态固定为：`待处理 / 处理中 / 待修改 / 已解决 / 已驳回`。

- 原始反馈不可覆盖、修改或删除。
- `FeedbackMessage` 保存用户补充和管理员回复，形成不可变多轮时间线。
- 管理员可多次回复和调整状态。
- 只有“待修改”状态允许用户追加说明和图片。
- 已解决或已驳回后，用户可在 7 天内申请重新处理一次并填写理由；状态回到待处理。超过期限只能新建反馈。
- 普通用户只能查看自己的反馈。
- 旧 `adminRemark` 迁移为第一条历史管理员回复。

旧状态映射：`open -> 待处理`、`processing -> 处理中`、`resolved -> 已解决`、`closed -> 已解决`。

### 5.2 附件

采用 `@fastify/multipart` 流式上传，采用与远端 Node 版本兼容的 `file-type` 检查真实文件签名。

- 只允许 JPG、PNG、WebP。
- 单张最大 5 MiB，每次最多 3 张。
- 扩展名、声明 MIME 和 magic number 必须匹配允许集合。
- 服务端生成随机存储键，不使用用户文件名拼路径。
- 文件存入蛋蛋校园独立的非公开目录，不放入 `/var/www/dd`，不使用 Supabase。
- 预览和下载只通过鉴权 API；只允许反馈本人和具备对应权限的有效管理员。
- 响应使用准确 Content-Type、`nosniff` 和受控 Content-Disposition，不暴露磁盘路径。
- 管理员可以隐藏违规附件，但不能物理删除。用户看到“附件已被管理员隐藏”；原因、操作者和时间写入审计。

### 5.3 未读

使用资源级已读状态记录任务、打听和反馈的最后查看时间或最后消息位置。新状态、新回复和新补充产生通知。打开具体详情才更新该记录，进入标签页不批量清除。

## 6. 数据迁移与兼容

- 所有 schema 改动只增不删，保留现有用户、手机号字段、任务、打听、反馈和业务关联。
- 迁移旧 `User.role=admin` 到 RBAC 授权；过渡期保留旧字段，但授权服务不再信任它。
- 固定管理员初始化使用可重复、带保护条件的部署步骤，不在迁移 SQL 中写密码。
- 前端旧的“我的打听”和“我的反馈”入口改为新的标签跳转，旧通知仍可打开对应详情。
- “航线”根站和 Supabase 不在迁移、文件上传、Nginx 静态目录或数据库连接范围内。

## 7. 错误与安全边界

- 默认拒绝未知权限和未登记资源动作。
- 所有管理写操作在服务端校验，不依赖隐藏按钮。
- 角色授权、资料修改、反馈状态和审计必须在一致的事务边界内。
- 上传流超限、格式失败、请求中断或数据库失败时清理临时文件。
- 用户可见错误只包含稳定错误码对应的中文说明。
- 用户、角色、附件和聊天举报的敏感读取均写审计。
- 管理员权限到期时接口返回稳定 403，前端清理管理视图并回到普通用户界面。

## 8. 测试与验收

实现采用测试先行，至少覆盖：

- 资料二次编辑、唯一约束、昵称 30 天冷却、固定管理员昵称锁定。
- 邮箱修改清除验证时间，个人资料与盲盒数据同步。
- 四标签结构、逐条未读、旧入口跳转。
- 打听发布后查询成功，任何响应不暴露 `Route GET`。
- 首次强制改密、旧会话撤销、固定管理员保护。
- 多角色权限并集、各自期限、永久授权、即时撤销和角色停用。
- 权限变更对已打开会话立即生效。
- 反馈状态转移、多轮消息、7 天内仅重开一次。
- 附件数量、大小、真实格式、路径安全、越权读取和隐藏审计。
- 聊天举报只返回有限上下文，普通管理员无法浏览全部私聊。
- 管理员模式切换、公开标签和减少动态效果。

发布门槛：本地全量测试、TypeScript 构建、Prisma 校验和前端脚本语法全部通过；生产按数据库备份、增量上传、本地构建产物、Nginx 校验、PM2 日志、健康接口和公网烟测执行。PM2 `online` 不能替代日志和业务验证。

## 9. 回滚

- 发布前保留数据库压缩备份、旧后端目录、旧前端目录和 PM2 当前脚本路径。
- 新表和新增列在回滚应用时保留，不执行破坏性逆迁移。
- 若授权服务异常，切回旧应用目录和旧静态目录，核对日志与 `/dd/health`。
- 若附件服务异常，停止新上传但保留已有元数据和文件，不自动删除。

## 10. 明确不做

- 不引入独立授权服务或第二种数据库。
- 不搬运第三方客服后台或管理壳。
- 不允许管理员任意查看私聊。
- 不公开内部自定义角色名称。
- 不把临时密码、数据库密码、JWT、附件真实路径或短信密钥写入仓库和文档。
- 不在本轮删除手机号历史字段。
