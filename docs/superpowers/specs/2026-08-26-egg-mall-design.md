# 蛋蛋商城需求设计

日期：2026-08-26  
状态：已确认；已按 2026-08-26 平台 RBAC 方案修订

## 1. 产品目标与范围

蛋蛋商城是“蛋蛋校园”的集成式商城模块，复用现有登录、规范化 RBAC、蛋蛋币账户、蛋蛋币流水、通知和审计日志。商城不接入真实支付，蛋蛋币由现有任务和活动体系产生。

第一期同时支持虚拟商品和实物商品。普通用户只能购买，不能发布商品。管理员可以管理全部商城业务；管理员还可以按用户 ID 授予或撤销商品发布者权限。

第一期不包含用户之间转卖/赠送、真实货币充值、第三方物流 API、第二套商城专用授权体系、实物退货物流闭环和商家分账。

## 2. 角色与权限

### 普通用户（student）

- 浏览、搜索、筛选、排序商品。
- 将商品加入购物车并使用蛋蛋币购买。
- 维护收货地址，查看订单和虚拟权益。
- 取消未发货订单并申请退款。
- 确认收货、评价已完成订单。
- 接收商城站内通知。
- 无法创建、编辑、审核、上架、下架或删除商品。

### 商品发布者

商品发布者不是新的 `User.role` 枚举值，也不建立 `ProductPublisherPermission`。平台在统一 RBAC 中预置“商品发布者”角色，由 `Role`、`Permission`、`RolePermission` 和 `UserRoleGrant` 表达权限与期限。只有两个固定管理员可以授予、续期、永久化或撤销该角色，所有变更进入 `RoleGrantAudit`。

- 可创建、编辑自己发布的商品。
- 可上传图片、填写建议价格、配置库存、限购和虚拟发放内容。
- 可查看自己商品的浏览量、销量、销售额、库存和订单数量，并支持商品、订单状态和时间范围筛选。
- 不能直接上架；提交后必须进入管理员审核。
- 不能管理他人的商品、订单、买家信息、蛋蛋币、评价审核或发布者权限。
- 授权期限复用统一 RBAC 的 1 小时、7 天、1 个月、1 季度、永久和自定义时间；下一个请求立即按有效授权重新判定。
- 用户拥有多个有效角色时权限取并集；只有所有角色都不再提供商品发布权限，才视为发布能力失效。
- 发布能力撤销、到期或角色停用后，未售罄商品自动下架；历史订单、权益和评价保留，具备商品管理权限的管理员可手动重新上架或转交。

### 管理员

- 管理能力由当前有效权限决定，不再信任 JWT 中的 `role` 或旧 `User.role=admin`。
- 商品、分类、兑换码、订单、库存、发货、售后、评价、蛋蛋币调整和商城日志分别使用独立权限键，可按角色勾选。
- 审核、定价、库存、上架、退款和蛋蛋币调整互相独立；前端隐藏按钮不能代替服务端鉴权。
- 只有两个固定管理员可以进入“用户与权限”授予、延期或撤销商品发布者角色；其他管理员即使拥有商城管理权限也不能转授权限。
- 增加或扣除用户蛋蛋币必须拥有对应权限、填写原因并写入审计日志。

## 3. 用户端页面

### 商城首页

提供关键词搜索、商品类型/自定义分类筛选和按上架时间、价格、销量排序。商品卡片展示主图、名称、类型、价格、库存或售罄状态、销量、简短描述和发布者标识。

### 商品详情页

展示主图、详情图、商品名称、类型、价格、详情说明、库存、限购规则、购买数量、当前蛋蛋币余额、发布者和评价列表。购买前弹窗确认实时价格、数量和实付蛋蛋币。

### 购物车

支持加入、移除和修改数量。登录用户购物车保存到数据库并跨设备同步；未登录用户仅保存在浏览器临时状态，登录后可合并。商品下架、售罄、价格或限购变化时标记信息已变化，不能直接结算。

### 订单中心

支持全部、待发货、已发货、已完成、已取消、异常筛选。订单详情显示商品快照、数量、实付蛋蛋币、地址快照、物流信息、虚拟发放结果和售后状态。

### 我的权益

展示已获得虚拟商品、权益类型、获得时间、使用状态、兑换码和剩余有效期；兑换码支持复制。

### 收货地址

支持新增、编辑、删除和设置默认地址。下单时选择地址，订单保存不可变地址快照。

## 4. 管理端页面

提供独立商城后台，按当前有效权限展示商品管理、分类管理、兑换码管理、订单管理、库存管理、发货管理、售后/退款管理、评价管理、蛋蛋币调整和操作日志。“商品发布者授权”复用平台“用户与权限”页面，不在商城内建立第二套授权界面。

## 5. 商品规则与生命周期

商品类型为 `virtual` 或 `physical`。虚拟商品不限库存（兑换码型商品仍受兑换码数量限制）；实物商品必须设置库存，售罄后不可购买，可由管理员补库存。

商品状态：`draft`、`pending_review`、`rejected`、`approved`、`on_sale`、`off_sale`、`archived`、`sold_out`。

- 发布者创建商品后为草稿，提交后为待审核。
- 管理员审核通过并确认最终价格后才能上架。
- 管理员可新增、编辑、上架、下架、删除/归档商品。
- 发布者修改已上架商品的名称、类型、价格、库存、发放规则或图片时，自动回到待审核。
- 删除采用归档语义；有订单关联的商品不能物理删除。
- 商品保存发布者 ID 和昵称快照；平台商品可标记为官方/平台精选。
- 销售收入统一归平台统计，不给发布者自动增加蛋蛋币。

## 6. 数据模型

### 权限依赖

商城不新增发布者授权表。统一 RBAC 预置商品发布者角色及商城权限键，授权有效性、期限、撤销、角色停用和审计复用 `UserRoleGrant` 与 `RoleGrantAudit`。`Product.publisherId` 只表达商品归属，不能作为当前授权依据。

首期商城权限目录至少包含：`shop.product.create_own`、`shop.product.edit_own`、`shop.product.submit_own`、`shop.product.stats_own`、`shop.product.view_all`、`shop.product.review`、`shop.product.publish`、`shop.product.archive`、`shop.category.manage`、`shop.inventory.manage`、`shop.redeem_code.manage`、`shop.order.view`、`shop.order.ship`、`shop.order.refund`、`shop.review.moderate` 和 `shop.audit.view`。蛋蛋币查看、调整和退款复用平台已有的蛋蛋币权限键。

### 商品

`Product` 保存发布者、昵称快照、名称、类型、分类、描述、主图、详情图、价格、库存、是否不限库存、购买数量规则、虚拟商品类型与 JSON 发放内容、状态、审核信息和时间字段。图片可使用 `ProductImage` 保存主图/详情图、排序和删除信息；第一期文件存服务器指定目录，数据库保存相对 URL。

### 购物车

`ShopCartItem`：`id`、`userId`、`productId`、`quantity`、`createdAt`、`updatedAt`；`userId + productId` 唯一。

### 订单

`ShopOrder` 保存 `userId`、状态、总金额、是否需要发货、收货人/电话/地址快照、快递公司、运单号、发货/完成时间、取消/退款原因和时间字段。`ShopOrderItem` 保存订单、商品 ID、商品名称/类型/价格快照、数量、虚拟发放状态与发放内容。

订单状态：`paid`、`awaiting_shipment`、`shipped`、`completed`、`cancel_requested`、`cancelled`、`refunding`、`refunded`、`failed`。

### 地址、权益、兑换码、评价

- `ShippingAddress`：用户地址簿和默认地址；删除不影响订单快照。
- `UserEntitlement`：用户、商品、订单明细、权益类型、JSON 内容、状态、获得和过期时间。
- `ProductRedeemCode`：商品、兑换码哈希/掩码、可用/已分配/已使用状态、关联订单明细和使用时间。
- `ProductReview`：商品、订单明细、用户、1-5 分、留言、可见/隐藏状态和隐藏原因；同一订单明细只能评价一次。

## 7. 下单与蛋蛋币事务

购物车支持虚拟和实物商品混合。结算时服务端必须重新读取实时价格、库存、限购和兑换码数量，前端价格不可信。实物商品必须有有效地址。

多商品下单在一个数据库事务内完成：锁定商品和蛋蛋币账户，校验所有商品，扣减实物库存，创建订单和明细，使用现有 `PointAccount`/`PointTransaction` 扣除蛋蛋币，发放虚拟权益或分配兑换码，创建通知，清除购物车项，然后提交事务。任一商品失败则整单回滚。

下单要求客户端提供 `idempotencyKey`。重复提交同一幂等键返回原订单，不重复扣币、扣库存或发放权益。库存和余额必须防止并发超卖和负数。

虚拟订单购买成功即完成；实物订单进入待发货，管理员填写快递公司和运单号后为已发货，用户确认收货或超过 15 天自动完成。混合订单按明细分别展示状态，整体状态根据实物明细和虚拟发放结果计算。

未发货订单可申请取消，管理员审核后退回蛋蛋币；已发货订单不支持线上退款。退款使用独立幂等键。

## 8. API 边界

用户端：`/api/shop/products`、`/api/shop/cart`、`/api/shop/orders`、`/api/shop/entitlements`、`/api/shop/addresses` 及其资源操作。

发布者端：`/api/shop/publisher/products`、`/api/shop/publisher/products/:id/submit-review`、`/api/shop/publisher/products/:id/stats`。

管理员端：`/api/admin/shop/products`、`/api/admin/shop/orders`、`/api/admin/shop/reviews` 及审核、上架、下架、归档、发货、退款和评价处理操作。发布者角色的授予、续期和撤销统一走平台 RBAC 接口，不提供 `/api/admin/shop/publishers` 第二套授权 API。

## 9. 安全、隐私与错误处理

- 所有接口要求登录；管理接口逐项校验商城权限；发布者接口实时构建 CASL Ability，并同时校验自有资源范围。
- 商品文本、评价、退款原因和虚拟 JSON 内容复用现有敏感词过滤。
- 上传仅允许 JPG/PNG/WebP，服务端检测 MIME/文件内容、限制大小和数量、随机命名并禁止路径拼接。
- 商品详情渲染必须转义 HTML；兑换码数据库保存哈希和掩码。
- 收货地址只对本人和处理订单的管理员可见；发布者只能看自己商品汇总，不可看买家隐私和平台总收入。
- 统一返回结构 `{ error, message }`，覆盖商品下架、库存不足、余额不足、限购超限、缺少地址、已发货不可取消、兑换码不足、权限失效和上传失败等错误。

定时任务将超过 15 天未确认的已发货订单自动完成，并找出已经失去全部有效商品发布权限的发布者、下架其未售罄商品；任务必须幂等。RBAC 授权不需要额外改写为 expired，是否有效由服务端时间实时计算。若暂时没有调度器，提供受权限保护的手动触发接口并记录部署执行方式。

## 10. 通知、审计与验收

购买成功、虚拟发放成功/失败、实物发货、取消退款、售后结果、商品下架和权限变化接入现有站内通知中心。授权、审核、改价、改库存、发货、退款、评价隐藏和蛋蛋币调整写入 `AuditLog`。

后端测试必须覆盖角色隔离、授权有效期、商品审核、发布者越权、多商品事务回滚、并发库存、幂等下单、虚拟发放、地址快照、发货/自动完成、取消退款、评价唯一性和统计隐私。前端测试覆盖商城浏览、购物车、结算、混合订单、订单中心、地址、权益、发布者工作台和管理员后台。

## 11. 验收结论

当没有发布权限的普通用户无法发布商品，两个固定管理员可通过统一 RBAC 按用户授予限时或永久的商品发布者角色，具备对应权限的管理员可完成审核和运营，用户可用现有蛋蛋币购买虚拟/实物商品并完成相应交付，订单、库存、通知、评价、退款和审计均可追溯时，本需求视为完成。
