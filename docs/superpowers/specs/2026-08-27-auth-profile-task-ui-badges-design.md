# 蛋蛋校园登录状态、注册、角色档案、任务卡与消息角标设计

## 目标

在不整体重写现有页面、不删除现有 REST 接口、不启用商城的前提下，解决以下五项线上问题：

1. 登录状态已恢复，但个人页仍显示“未登录”。
2. 个人页的蛋蛋角色展示缺少清晰、稳定的视觉层级。
3. 正式网站完整填写注册表单后返回“注册服务暂时不可用”。
4. 任务广场卡片需要采用参考图的信息结构，并以更鲜明的校园潮玩视觉呈现。
5. 消息入口始终可见；未处理数量为零时只隐藏数字角标。

## 已确认边界

- 采用轻量全局状态层，不引入 React、Vue、Tailwind 或新的前端框架。
- 登录凭证继续使用内存 access token 和 HttpOnly refresh cookie，不向 `localStorage` 写入 token。
- 商城继续由前后端开关关闭，不执行商城迁移。
- 不触碰“航线”项目或 Supabase。
- 注册不再提供手机号输入或手机号登录。
- 用户名和密码必填，密码不少于 8 位；邮箱、学校、专业、城市、年级、邀请码及其他资料均为选填。
- 填写邮箱不要求验证码，也不进入验证码校验分支。
- 任务、用户、奖励、人数、角色和消息数量全部来自现有后端接口，不添加生产演示数据。
- 当前五项改造不使用风景图片；真实蛋蛋角色图片已经承担业务视觉信息，装饰性风景图会降低操作界面的可读性。

## 状态架构

新增浏览器端轻量状态模块 `DandanAppState`，作为认证身份与未读数量的唯一前端事实来源。

状态结构：

- `authStatus`: `restoring | authenticated | guest`
- `currentUser`: 当前登录用户的服务端资料；访客为 `null`
- `currentCharacter`: 当前已解锁并正在使用的蛋蛋角色；无记录时为 `null`
- `unreadCounts`: 通知、打听、反馈、任务待处理和盲盒消息的非负整数计数

状态模块提供：

- `getState()`：读取只读快照。
- `setState(patch)`：由认证或数据同步流程更新状态。
- `subscribe(listener)`：页面组件订阅变化，返回取消订阅函数。
- `setUnreadCount(key, value)`：统一归一化未读数量，非法值按零处理。
- `reset()`：退出登录时清除用户、角色和私有未读状态。

状态模块不保存任务列表、排行榜或其他大体量业务集合。这些数据仍由既有 REST 接口和页面加载函数管理，避免把五项修复扩展成全站重写。

## 登录与个人页数据流

1. 页面启动将 `authStatus` 设为 `restoring`，避免在 refresh cookie 校验完成前误显示“未登录”。
2. `restoreSession()` 成功后，将 `/api/users/me` 返回的完整用户资料写入 `currentUser`。
3. 登录和注册成功走同一状态写入函数，不再分别维护侧边栏和个人页数据。
4. 修改个人资料成功后重新调用 `/api/users/me`，用服务端结果替换状态快照。
5. 个人页右上角、侧边栏用户卡和管理员身份展示全部订阅同一 `currentUser`。
6. 只有 `authStatus === guest` 时显示“未登录”；已登录但学校为空时显示“学校未填写”。
7. 退出登录调用状态 `reset()`，所有订阅组件同步回访客状态。

## 注册修复

### 服务端规则

- `nickname` 与 `password` 为必填字段，密码长度不少于 8。
- `email` 为可选联系资料；提供邮箱时只执行格式、唯一性和敏感词校验，不创建或消费验证码记录。
- 手机号不作为本次注册输入，不提供手机号认证分支。
- 邀请码仍按现有邀请关系规则校验；空邀请码不创建邀请关系。
- 重复昵称或邮箱返回 `409` 和中文业务提示。
- 参数错误返回 `400` 和具体中文提示。
- 数据库不可用返回稳定 `503`，日志只记录错误类型和请求标识，不输出连接串或密码。

### 生产诊断顺序

1. 使用指定磁盘私钥读取生产后端当前 PID 的注册错误日志，不输出环境变量值。
2. 区分 Prisma schema 缺失、数据库连接失败、字段约束冲突和旧验证码分支。
3. 先在测试中复现确定根因，再做最小修复。
4. 若生产缺少已经批准的非商城迁移，只执行目标 SQL 并核对迁移状态；禁止运行会扫描商城迁移的全量 `prisma migrate deploy`。

## 个人页角色档案

采用已批准的“角色档案卡”方向：

- 使用当前角色的真实蛋蛋图片。
- 展示真实角色名称、角色类型、解锁状态和“当前使用”状态。
- 当前 `UserCharacter` 只有 `category`、`unlocked`、`count`、`isCurrent` 和 `unlockedAt`，不存在角色等级字段；禁止显示 `LV.6` 一类虚构角色等级。
- 如需展示成长等级，只能使用服务端用户经验值 `exp` 通过现有 `getLevel()` 规则得出的用户等级，并明确标为“用户成长等级”，不能冒充角色等级。
- 未取得角色时显示明确空状态，不生成虚假成长进度或默认满属性。
- 档案卡保持浅色主体、莓果粉识别边框和电光紫状态标签；角色图片为视觉焦点。
- 卡片圆角不超过 8px，避免与现有工具界面风格脱节。
- 个人页右上角继续显示用户名和学校；中部已删除的旧用户长条不恢复。
- MPI 蛋蛋小人、个人统计、编辑资料及其他现有功能保持不变。

## 任务广场卡片

采用用户参考图的信息顺序和已批准的“高饱和潮玩粉”方向：

1. 标题与任务类型。
2. 分类、审核状态、组队方式及人数类型等关键标签，首屏最多显示四项。
3. 发布者真实蛋蛋头像、昵称和角色摘要。
4. 经验与蛋蛋币奖励；奖励为空或为零时按现有业务规则显示，不伪造数值。
5. 两至三行任务描述。
6. 当前人数与人数上限。
7. 查看详情图标按钮，继续调用现有详情逻辑。

视觉系统：

- 主强调为莓果粉，次强调为电光紫。
- 审核、协作、奖励等状态分别使用青绿、湖蓝、明黄，避免整页单一粉色。
- 卡片主体为高对比浅色，不把正文放在高饱和底色上。
- 桌面两列；移动端单列。发布者、奖励和标签允许换行，不出现内部横向滚动。
- 悬停只上移 2px；真实状态更新允许一次短促闪亮。统一缓动为 `cubic-bezier(0.16, 1, 0.3, 1)`。
- `prefers-reduced-motion` 下禁用非必要动效。

## 消息角标

- 消息入口按钮、边框和图标始终渲染并可点击。
- 数字角标只有在规范化数量大于零时显示。
- 数量为零、空值、负数或非法值时，角标使用 `hidden` 属性或等价的 `display:none`，不能显示字符 `0`。
- 回复、阅读、审核或处理完成后，相关模块重新读取服务端计数并更新 `unreadCounts`；降至零立即隐藏角标。
- 用户总数、任务总数、排行榜人数等普通统计不属于消息角标，允许显示零。

## Apogee 提示词的采用范围

只采用其工程化设计方法：

- 明确记录卡片内边距、按钮高度、间距和响应式尺寸。
- 使用一致的缓动曲线和延迟规则。
- 验证按钮文字与边框之间的实际留白。
- 验证每个响应式断点下的换行和溢出。
- 基础悬停和按压反馈使用 CSS；任务列表编排按下文采用本地 anime.js；两者都支持 reduced motion。

不采用 Apogee 的 React/Tailwind 技术栈、品牌名、英文文案、CloudFront 视频、深色 Hero、玻璃收入卡或原始像素值。

## 开源 UI 与动效采用范围

完整选型与来源见 `docs/research/2026-08-27-ui-motion-open-source-options.md`。

### anime.js

- 采用官方 `animejs@4.5.0` ESM 压缩包，本地随站点部署并保留 MIT 许可证，不依赖外部 CDN。
- 只在用户进入任务广场且未启用减少动态效果时懒加载。
- 任务卡首次展示：`translateY(12px)` 到零、透明度到 1、持续 360ms、卡片间隔 36ms。
- 筛选重排持续 240ms 至 320ms；真实状态更新只允许一次 420ms 边框高亮。
- 旧动画在页面切换或列表重绘前取消；加载失败立即回退为无动画最终状态，业务功能不得受影响。

### Uiverse

- 参考 Uiverse Galaxy 的 `Cards/Admin12121_purple-parrot-82.html`，只复用悬停强调层、轻微上移和按压回落的关系。
- 按蛋蛋校园 DOM 和色彩重写，不复制其固定尺寸、教育 SVG、文案或整面覆盖效果。
- 在第三方声明中注明 `Uiverse.io / Admin12121` 与 MIT 来源。

### Aceternity UI

- 参考 Hover Border Gradient 的“边框强调、正文稳定”原则。
- 不复制 React 组件，不引入 Next.js、Tailwind、Motion、`clsx` 或 `tailwind-merge`。
- 任务卡只保留静态彩色顶边和状态更新时的一次性高亮，不采用持续旋转边框或鼠标追踪聚光灯。

### 动效降级

- `prefers-reduced-motion: reduce` 下不动态导入 anime.js，所有内容直接显示最终状态。
- 动画只改变 `transform` 和 `opacity`，不能改变卡片固定几何尺寸或触发横向溢出。
- 动画模块失败只允许一次受控日志，不得重复刷屏。

## 错误处理

- 会话恢复失败：确认 refresh 失败后再进入 `guest`，不在请求未完成时显示“未登录”。
- 用户资料部分接口失败：保留已确认的登录身份，局部展示“资料暂时无法加载”，不能把用户降级为访客。
- 注册参数错误：展示后端中文业务提示并聚焦对应输入。
- 注册数据库错误：展示稳定服务提示，同时通过服务器日志定位根因。
- 未读计数接口失败：保留入口框，隐藏未知数字角标，并允许用户手动进入查看。
- WebSocket 断线：继续使用现有 REST 全量拉取兜底，不由本次状态模块直接写业务数据。

## 测试与验收

### 自动化测试

- 状态模块：恢复、登录、资料刷新、退出和订阅取消。
- 个人页：已登录用户不出现“未登录”；学校空值显示“学校未填写”。
- 角色档案：只消费真实角色字段，不生成虚假数值。
- 动效：anime.js 懒加载成功时只作用于任务卡；加载失败和减少动态效果模式下业务仍完整可用。
- 注册：仅用户名密码成功；选填邮箱成功且不查询验证码；全资料表单成功；重复字段和数据库异常返回稳定中文错误。
- 任务卡：真实字段全部存在，旧详情、筛选、审核和接取入口仍可达。
- 角标：零隐藏、正数显示、处理后归零隐藏，入口框始终存在。
- 响应式：390x844、768x1024、1440x900 无横向溢出和文字遮挡。

### 发布门禁

1. 本机定向测试先红后绿。
2. 完整 Vitest、TypeScript 构建、前端脚本解析和 `git diff --check` 通过。
3. 隔离数据库完整 E2E 通过，覆盖注册、登录恢复、资料、任务和实时计数刷新。
4. 只上传哈希变化的前端文件、后端构建文件和必要非商城迁移。
5. 服务器不执行 build，不删除 `node_modules`，不修改无关 `.env`。
6. 发布后检查注册、登录恢复、个人页、任务广场、角标、health、Nginx、PM2 和当前 PID 日志。
7. 更新任务计划、测试报告、进度文件和 Obsidian 变更日志。

## 验收结论标准

- 同一会话中侧边栏和个人页登录身份一致。
- 个人页角色档案使用真实角色数据且达到批准的视觉方向。
- 线上完整填写选填资料可以注册，邮箱不要求验证码。
- 任务卡达到批准的信息层级和潮玩视觉，所有原业务操作保持可用。
- 所有消息入口框持续显示，零数量不显示数字角标。
- 生产无新增 5xx、MySQL 1045、Prisma 初始化错误或商城暴露。
