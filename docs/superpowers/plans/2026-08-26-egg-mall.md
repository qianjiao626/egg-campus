# 蛋蛋商城 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在蛋蛋校园现有 Fastify + Prisma + 单页前端中实现蛋蛋商城，支持管理员审核和管理商品、商品发布者授权发布、虚实混合购物车下单、蛋蛋币原子扣款、虚拟权益发放、实物发货、订单售后和评价。

**Architecture:** 复用平台 User、统一 RBAC、PointAccount、PointTransaction、Notification、AuditLog 和认证中间件；在 Prisma 中增加商城领域表，在后端以 `shop` 路由模块承载用户/发布者 API、以 `admin/shop` 路由承载管理 API。前端沿用 `growth-school.html` 与 `api-client.js` 的单页导航和状态模式，增加商城用户页、发布者工作台和管理员后台区块。

**Tech Stack:** TypeScript, Fastify 5, Prisma 6, MySQL/MariaDB, Zod, Vitest, 原生 HTML/CSS/JavaScript。

## Global Constraints

- 商城实施必须以 `docs/superpowers/specs/2026-08-26-profile-feedback-rbac-design.md` 的统一 RBAC 落地为前置；不能新增 `ProductPublisherPermission`，不能使用 JWT `role` 或旧 `User.role` 作为最终授权。
- 商品发布者使用预置 RBAC 角色与 `UserRoleGrant`；只有两个固定管理员可以授予、续期、永久化和撤销该角色。
- 商城管理动作使用细粒度权限键；资源查询同时强制商品归属或管理范围。
- 商城只使用现有蛋蛋币，不接入真实支付；所有扣币必须写入 `PointTransaction` 并具备幂等键。
- 普通用户不能发布商品；发布者不能调用管理员接口或查看买家隐私。
- 虚拟商品不限库存但兑换码受码池数量限制，实物商品必须限制库存。
- 订单支持购物车多商品及虚实混合；下单校验、库存、扣币、权益发放在同一事务中完成。
- 图片第一期保存服务器本地目录，数据库只保存相对 URL；上传限制 JPG/PNG/WebP、大小和数量。
- 商品和评价文本复用现有敏感词过滤，详情渲染必须转义 HTML。
- 不修改用户已有未提交的 `server/cvm-deploy.sh`、认证测试等无关变更。

### Task 4: Connect publisher RBAC and admin shop APIs

**Files:**
- Modify: `server/src/app.ts`
- Modify: `server/tests/shop-contract.test.ts`

**Interfaces:**
- Publisher routes: `POST/PATCH /api/shop/publisher/products`, `POST /api/shop/publisher/products/:id/submit-review`, `GET /api/shop/publisher/products/:id/stats`.
- Admin routes: `/api/admin/shop/products`, `/api/admin/shop/orders`, `/api/admin/shop/reviews`, plus review/publish/off-sale/archive/shipment/refund operations. Publisher role assignment remains in the shared RBAC API.

- [ ] **Step 1: Add failing permission tests**

Assert denial without ability, multi-role union, expired/revoked/disabled grant behavior, publisher ownership isolation, and automatic off-sale only after the user loses every role that grants publishing.

- [ ] **Step 2: Implement grant/revoke/expiry**

Seed the product-publisher role and permission keys through the shared idempotent RBAC seed path. Reuse shared grant timestamps and `RoleGrantAudit`; do not create or mutate a shop-specific permission record. On effective capability loss, update unsold publisher products to `off_sale` and notify the publisher.

- [ ] **Step 3: Implement publisher product CRUD**

Allow draft creation and edits only for owned products; edits to important fields on sale return to `pending_review`; support stats filtered by product/status/time without buyer data.

- [ ] **Step 4: Implement admin moderation**

Allow each final price/inventory/rules edit, approve/reject, publish/off-sale/archive, inventory replenishment, shipment, refund and review-hiding action only when its exact permission is present; audit every action.

- [ ] **Step 5: Run tests and commit**

Run `npm test -- shop-contract.test.ts`; then commit with `git add server/src/app.ts server/tests/shop-contract.test.ts && git commit -m "feat: add publisher permissions and shop administration"`.
