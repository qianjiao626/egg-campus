# 蛋蛋校园认证产品规则

## 注册流程

1. 用户填写邮箱；可选填写手机号。填写手机号时优先使用短信验证，否则使用邮箱验证。
2. 客户端调用 `POST /api/auth/verification-codes` 请求验证码。
3. 用户输入 6 位验证码，客户端调用 `POST /api/auth/verification-codes/verify`。
4. 服务端返回短期、单用途 `verificationToken`；客户端只能把它提交给注册接口。
5. 客户端提交昵称、密码、资料和 token 到 `POST /api/auth/register`。
6. 服务端在事务中校验并消费 token，再创建用户、统计、角色、蛋蛋币账户和注册奖励。

## 验证码规则

- 验证码为 6 位数字，数据库只保存 SHA-256 哈希。
- 有效期 5 分钟；验证成功后立即消费，不能重复使用。
- 单个验证码最多输错 5 次；超过次数、过期或已消费统一返回 `INVALID_VERIFICATION_CODE`。
- 同一目标 60 秒内不可重发；每个目标每小时最多 5 次，每个 IP 每小时最多 20 次。
- 验证码、验证码 token、短信密钥和密码不得写入日志、响应或浏览器持久化存储。

## 登录和会话

- 登录标识支持邮箱、手机号或昵称。
- 登录失败、账号不存在、账号被停用和密码错误使用同一错误文案。
- access token 有效期 15 分钟；数据库 refresh session 最长 30 天。
- refresh token 每次刷新轮换，旧值不能再次使用；退出登录撤销当前会话。

## 找回密码

- `POST /api/auth/password-reset/request` 对未知账号和已知账号返回完全相同的成功响应。
- 找回验证码只用于 `reset_password`，不能拿来注册。
- 修改密码后撤销该用户全部现存会话。

## 验收案例

- 新用户能申请验证码、验证验证码、注册并自动登录。
- 重复邮箱/手机号/昵称注册返回冲突，不创建半成品用户。
- 错误、过期、重复使用和超过次数的验证码均失败。
- 登录、刷新、重复使用旧 refresh token、退出登录行为符合会话规则。
- 找回密码不会泄露账号是否存在，重置后旧会话失效。
- 蛋蛋校园只连接 `dandan_world` MariaDB；“航线” Supabase 不被读取、迁移或修改。
