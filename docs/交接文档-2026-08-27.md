# 蛋蛋校园项目交接文档

## 1. 一句话现状

蛋蛋校园已部署并运行在 `https://dsxnb.com/dd/`。它是独立于“航线”站点的 Node/Fastify + Prisma + CVM 本机 MariaDB 项目；主站的注册登录、任务、个人资料、盲盒交友、打听、反馈、邀请码、排行榜、RBAC 管理和实时通知均有实现与测试证据。

商城相关代码和数据库迁移仍保留，但前端和后端开关都处于关闭状态，当前不应继续上线或讨论商城改动，除非重新建立单独需求与验收范围。

## 3. 已交付功能

### 认证与账号

- 注册：昵称和密码必填，密码长度 8-128 位；邮箱选填，不要求验证码；手机号不参与注册或登录。
- 登录：昵称或邮箱登录；退出会撤销服务端会话。
- 登录持久化：access token 只保存在内存，refresh session 使用 HttpOnly Cookie；刷新或重新打开页面会调用 refresh + `/api/users/me` 恢复会话。
- 找回密码：仅邮箱验证码；验证码 provider 当前关闭，未配置短信能力。
- 管理员：使用统一 RBAC 角色和权限校验，管理员界面与普通用户界面可切换；管理员标识显示为“管理员”，不暴露“根管理员”等内部称谓。

### 用户与个人页

- 个人资料支持二次编辑：昵称、学校、专业、年级、城市、年龄、MBTI、简介、兴趣和技能标签。
- 侧边栏与个人页使用 `DandanAppState` 读取同一认证用户，避免“已登录但个人页显示未登录”。
- 角色护照保留 MPI 蛋蛋组件，展示真实角色、稀有度、完成次数、蛋蛋币和经验数据；无角色时显示空状态。
- 用户公开名片仅按稳定用户 ID 请求公开资料；未公开信息显示空状态，不伪造默认身份、分数或余额。

### 任务与反馈

- 任务发布、草稿、审核、公开、认领、放弃、提交、完成、评价和协商取消均走 REST 接口与 MySQL 持久化。
- 可见性规则：草稿仅发布者；待审核任务由具备权限的管理员读取；审核后的公开任务由合法登录用户读取。前端不再自行过滤权限。
- 任务接取人数、接取标识和技能标签由后端返回，刷新不依赖本地计数。
- “我的任务”集中展示已发布、已认领、我的打听和我的反馈；普通用户只可查看自己的历史反馈。
- 反馈支持工单、状态、管理员回复、补充后回到“待修改”、附件上传下载与用户/管理员权限隔离。

### 社交与内容

- 盲盒交友以 iframe 内容组件嵌入主站，复用主站外壳；含偏好、抽取、推荐、好友申请、好友聊天、留言、试题盲盒和玩法中心。
- 好友关系规则：不可重复申请；待处理、已拒绝冷却、已是好友分别提示；只有已接受好友可聊天。
- 打听树洞支持发布、回复、评论、点赞、采纳和悬赏结算；展示数据从接口回读，已清理前端模拟记录。
- 排行榜读取后端真实数据。
- 邀请码支持生成、填写、校验、关系记录与奖励；重复邀请会拦截。

### 实时能力与界面

- WebSocket 仅作为事件通知；业务数据仍通过 REST 重新拉取，断线后可降级刷新。
- 覆盖任务、盲盒、打听、反馈和排行榜的主要刷新事件，并按页面路由绑定/销毁监听。
- 五个消息入口的数字为 0 时隐藏数字，但入口容器保留显示。
- 任务广场已改为真实数据彩色卡片；移动端反馈入口移至左侧栏，避免遮挡任务卡。
- 已引入本地 Anime 动效资源；保持 `prefers-reduced-motion` 兼容。

## 5. 近期修复与当前验证

### 最新修复：空 DOM 节点报错

用户反馈多个按钮，特别是注册流程，出现：

```text
Cannot set properties of null (setting 'textContent')
```

根因是个人页改版已经删除 `#profileLevel`，但 `refreshProfile()` 仍在注册成功、登录及资料刷新时尝试写入它。注册成功后会进入普通用户初始化，因此最容易复现。

处理方式：删除唯一过期写入，继续使用现存的 `#profileExp2` 展示经验值；未通过全局 `try/catch` 或吞错隐藏问题。

回归证据：

- `server/tests/profile-layout-contract.test.ts` 新增断言，先失败后通过。
- 定向测试：`6/6` 通过。
- `npm test -- --maxWorkers=1` 完整套件已执行。
- `npm run build` 在本机构建成功。
- 生产主页面和 `/dd/health` 均为 200；公开页面确认旧写入不存在。
- Nginx active，PM2 `dandan-world` online，最近错误日志为空。

## 6. 部署标准流程

### 6.1 前置规则

1. 先确认当前分支、`git status --short`、改动文件和测试范围，不能覆盖其他协作者的工作。
2. 只在本机执行 `npm run build`；CVM 不执行前端或后端 build。
3. 后续迭代保留服务器 `node_modules`，只上传变更文件，不做全量删除或全量覆盖。
4. 不读取、不打印、不提交 `.env`、密码、Cookie、JWT、验证码或私钥内容。
5. 不触碰“航线”项目、其根站路径、其 Supabase 项目或凭据。
6. 商城保持关闭，除非未来需求重新授权；不执行商城迁移。

### 6.2 SSH 约束

必须使用用户指定的磁盘私钥，禁止 `ssh-agent`、`ssh-add` 和密码登录：

```powershell
$key = 'C:\Users\梁惠\.ssh\id_ed25519'
ssh -i $key -o IdentitiesOnly=yes -o BatchMode=yes root@119.45.253.94 "systemctl is-active nginx"
```

注意：不要写成 `C:\Users$env:USERNAME.ssh\id_ed25519`，这会被 PowerShell 解析为错误路径。若需要动态目录，使用：

```powershell
$key = Join-Path $env:USERPROFILE '.ssh\id_ed25519'
```

### 6.3 只更新前端静态文件

适用于本次这类只修改 `growth-school.html`、`api-client.js` 或盲盒静态文件的更新。

```powershell
# 1) 本机校验和
(Get-FileHash 'backend-handoff-package\growth-school.html' -Algorithm SHA256).Hash

# 2) 远端备份。目录名改为本次发布日期和主题
ssh -i $key -o IdentitiesOnly=yes -o BatchMode=yes root@119.45.253.94 `
  "mkdir -p /root/deploy-backups/<release-name> && cp -p /var/www/dd/growth-school.html /root/deploy-backups/<release-name>/growth-school.html"

# 3) 上传到临时位置，不能直接覆盖线上正式文件
scp -i $key -o IdentitiesOnly=yes -o BatchMode=yes `
  'backend-handoff-package\growth-school.html' root@119.45.253.94:/tmp/growth-school.html

# 4) 对比远端临时文件哈希，确认完全一致后才安装
ssh -i $key -o IdentitiesOnly=yes -o BatchMode=yes root@119.45.253.94 "sha256sum /tmp/growth-school.html"

# 5) 原子覆盖、校验 Nginx、重载 Nginx
ssh -i $key -o IdentitiesOnly=yes -o BatchMode=yes root@119.45.253.94 `
  "install -m 644 /tmp/growth-school.html /var/www/dd/growth-school.html && nginx -t && systemctl reload nginx"
```

静态前端更新不需要重启 PM2。上传 `blind-box/app.js` 时同样先传到 `/tmp`，哈希通过后安装到 `/var/www/dd/blind-box/app.js`。

### 6.4 后端更新

仅当 `server/src/` 改动且本机已经构建成功时进行：

1. 本机 `cd server; npm test -- --maxWorkers=1`。
2. 本机 `npm run build`。
3. 只上传对应的构建产物和必要源码/配置文件到正式后端目录；不要上传 `.env`，不要删除远端 `node_modules`。
4. 先检查数据库迁移是否确实需要。没有新迁移时不得执行 `prisma migrate deploy`。
5. 必须重启时只重启正式进程：`pm2 restart dandan-world --update-env`。
6. 重启后立即查看日志，不允许仅凭 PM2 `online` 判定成功。

```powershell
ssh -i $key -o IdentitiesOnly=yes -o BatchMode=yes root@119.45.253.94 `
  "pm2 logs dandan-world --lines 80 --nostream --err"
```

若出现 MySQL `1045 Access denied`，优先停止重试，核查远端 `.env` 的 `DATABASE_URL` 是否包含正确账号、密码、地址和数据库名。不要反复重启应用掩盖配置错误。

### 6.5 发布后最低验收

```powershell
Invoke-WebRequest 'https://dsxnb.com/dd/growth-school.html' -UseBasicParsing
Invoke-WebRequest 'https://dsxnb.com/dd/health' -UseBasicParsing

ssh -i $key -o IdentitiesOnly=yes -o BatchMode=yes root@119.45.253.94 `
  "systemctl is-active nginx; pm2 status dandan-world --no-color; pm2 logs dandan-world --lines 80 --nostream --err"
```

预期：页面 200、health 200、Nginx active、`dandan-world` online、错误日志无新异常。

服务器本机用 `127.0.0.1` 直接请求时可能命中 Nginx 默认虚拟主机并得到假 404；优先使用公开 health 地址，或显式携带正确 `Host` 头。

### 6.6 静态文件回滚

```powershell
ssh -i $key -o IdentitiesOnly=yes -o BatchMode=yes root@119.45.253.94 `
  "install -m 644 /root/deploy-backups/<release-name>/growth-school.html /var/www/dd/growth-school.html && nginx -t && systemctl reload nginx"
```

回滚后仍须重复页面、health、Nginx 与 PM2 日志验收。

## 7. 已踩坑与处理经验

| 场景 | 真实问题 | 正确处理 |
| --- | --- | --- |
| 页面结构改版 | 删除 DOM 后遗留 `document.getElementById(...).textContent`，导致按钮链路崩溃 | 先查调用栈和数据流；为已删除节点删除过期写入或补回必要结构；添加失败回归，不要用全局吞错。 |
| 演示数据清理 | 清理 `GOSSIP_POSTS` 等模拟数据后，相关空数组/筛选状态未初始化 | 删除模拟数据时同步补足真实空状态和默认初始化；不要仅搜索“demo”关键字后机械删除。 |
| 注册失败提示 | 既可能是前端 DOM 运行时错误，也可能是 API 返回的数据库错误 | 先区分浏览器栈、网络响应和后端日志；前端应展示中文业务错误，后端区分参数、重复账号和数据库不可用。 |
| 多人协作 | 工作树长期存在大量未提交改动和生成文件 | 改动前读 `git status` 和目标文件 diff；只编辑自己的范围；绝不 reset、clean 或覆盖。 |
| PowerShell | `rg` 在当前 Windows 环境未安装；复杂引号、正则和 `$1` 容易被 PowerShell 改写 | 用 `Select-String`/小型独立命令替代；复杂流程拆成多条命令，每条读输出后再继续。 |
| SSH 私钥路径 | `C:\Users$env:USERNAME...` 不是有效 PowerShell 路径 | 使用固定绝对路径或 `Join-Path $env:USERPROFILE`；始终加入 `IdentitiesOnly=yes` 和 `BatchMode=yes`。 |
| PM2 | `online` 只说明进程存活，不说明服务连库或路由正常 | 每次后端更新后查看 error log、health 和关键鉴权 API；遇到 1045 先查环境变量。 |
| Nginx 本机探测 | 用 `127.0.0.1` 会落入默认站点，出现误导性的 404 | 使用 `https://dsxnb.com/dd/health` 或携带正确 Host 头。 |
| API 认证 | 未登录时会有预期的 401；不能把它误判为站点崩溃 | 匿名接口验证应断言 401，正式业务用隔离测试账号在测试库完成。 |
| 匿名页面请求 | 多个请求同时 401 时 `api-client.js` 会各自尝试 refresh，控制台可能出现重复 refresh 401 | 这是已知待优化项。后续可做单飞 refresh（single-flight）控制，但必须独立修复和验证，不要与无关 UI 补丁合并。 |
| 浏览器自动化 | 没有可用 CDP 或终端附着时，不能声称已真实点击测试 | 如实记录“未执行”；可用时按 agent-browser 的 CDP 流程连接，禁止伪造通过。 |
| 生产测试 | 直接使用生产真实账号会污染数据、泄露凭据 | 使用 `dandan_campus_test` 和端口 3311 的隔离环境；临时凭据只在进程内生成，不写入报告。 |
| 构建位置 | 在 CVM build 耗时且容易与生产依赖状态混淆 | 始终本机 build，服务器只接收已验证产物并运行。 |
| 商城 | 商城模型/测试存在，但当前产品决策为不展示、不上线 | 保留代码，维持 `data-shop-enabled="false"` 与后端关闭；不做迁移、不暴露入口。 |
