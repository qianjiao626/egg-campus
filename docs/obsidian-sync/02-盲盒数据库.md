# 盲盒数据库

## 登录与页面边界

盲盒页面是主站右侧的纯内容组件，地址为 `/dd/blind-box/`。它不再生成顶部导航、插件侧边栏、页脚或独立标题栏；主站侧边栏点击入口后直接渲染内容，不跳转到另一套外壳。

盲盒脚本使用同源 `/dd/api` 并携带 `credentials: 'include'`。因此盲盒登录状态复用主站的 HttpOnly refresh cookie；页面刷新或重新打开时由同一套 `/api/auth/refresh` 恢复。

## 已落库的基础业务

| 功能 | API | 数据表 |
|---|---|---|
| MBTI、兴趣、今日想法、地域、隐身设置 | `GET/PUT /api/buddy-box/preferences` | `buddy_preferences` |
| 用户推荐 | `GET /api/buddy-box/recommendations` | `users`，按公开字段脱敏 |
| 收件箱 | `GET /api/buddy-box/inbox` | `buddy_messages`、`buddy_friend_requests` |
| 发消息 | `POST /api/buddy-box/messages` | `buddy_messages` |
| 标记已读 | `POST /api/buddy-box/messages/:id/read` | `buddy_messages.read_at` |
| 好友申请/接受 | `POST /api/buddy-box/friend-requests`、`.../:id/accept` | `buddy_friend_requests` |

## 通用玩法记录

为保留全部前端接口插头，同时让每个操作归属当前用户，新增 `BuddyFeatureRecord` 和迁移 `20260824094000_buddy_feature_records`。

| 字段 | 用途 |
|---|---|
| `user_id` | 当前登录用户，服务端从会话取得 |
| `feature` / `action` | 玩法和动作，例如 `quiz/create`、`memory/create` |
| `payload` | 业务表单或动作参数 JSON |
| `result` | 服务端产生的结果 JSON |
| `status` | 当前记录状态 |
| `idempotency_key` | 防止重复点击产生重复记录 |
| `created_at` / `updated_at` | 审计和列表排序 |

接口：

- `POST /api/buddy-box/features`：写入当前用户的玩法动作，重复幂等键返回已有记录。
- `GET /api/buddy-box/features/:feature?scope=mine|public&limit=...`：读取当前用户记录或脱敏的公开记录。

前端 `buddy-box-api.js` 已将试题盲盒、反向盲盒、记忆盲盒、跨校、破冰、协作、回响、图鉴、雷达、问答墙、小组、心愿墙、安全和活动等 adapter 接到这两个通用接口，原有界面和接口名称保持不变。

## 诚实的完成边界

通用记录已经能按用户持久化 payload/result，但它不是所有高级玩法的最终领域模型。声望扣减/返还、试题审核解锁聊天、时间胶囊到期、好友关系和安全风控仍需要后端状态机、权限和事务规则；不能仅凭“记录写入成功”宣称这些规则已经生产闭环。后续优先把 `quiz`、`box`、`prestige` 三组规则从通用记录升级为可审计的业务事务，同时保留现有 adapter 兼容层。

## 数据隔离

盲盒只使用蛋蛋校园自己的 `dandan_world` MariaDB 表（`buddy_*` 和 `buddy_feature_records`），不读取“航线”的 Supabase URL、密钥、表或迁移。前端永远不直连数据库。

## 代码证据

- `server/prisma/schema.prisma`：`BuddyPreference`、`BuddyBox`、`BuddyMessage`、`BuddyFriendRequest`、`BuddyFeatureRecord`。
- `server/src/app.ts`：盲盒基础路由和通用玩法读写路由。
- `backend-handoff-package/blind-box/buddy-box-api.js`：adapter 与 API 映射。
- `backend-handoff-package/blind-box/app.js`：MBTI、资料、玩法中心和 UI 交互。
