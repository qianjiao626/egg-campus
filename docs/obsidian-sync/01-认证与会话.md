# 认证与会话

## 注册是否存在

注册功能已经存在，不是 Demo 空壳。后端入口为 `POST /api/auth/register`，前端由 `api-client.js` 调用；昵称和密码是必填项，邮箱和手机号均为可选联系方式，验证码也为可选。注册事务会创建用户、用户统计、角色、蛋蛋币账户和注册奖励。

## 当前流程

1. 用户填写昵称和密码；可选填写邮箱或手机号。
2. 如果用户希望验证联系方式，再由 `POST /api/auth/verification-codes` 申请验证码，并用 `POST /api/auth/verification-codes/verify` 得到一次性 `verificationToken`。
3. `POST /api/auth/register` 提交昵称、密码、资料和可选 token；没有 token 也可以注册。
4. 服务端建立会话并通过 HttpOnly refresh cookie 保存长期登录状态。
5. 页面启动时 `restoreSession()` 调用 `/api/auth/refresh`，再调用 `/api/users/me` 恢复用户资料和管理员/普通用户导航状态。

登录支持邮箱、手机号或昵称；退出调用 `POST /api/auth/logout`，服务端撤销会话并清理 Cookie。

## 持久化策略

| 数据 | 存放位置 | 生命周期 |
|---|---|---|
| access token | 前端内存 | 短期，页面重载后重新刷新 |
| refresh token | 服务端哈希 + 浏览器 HttpOnly Cookie | 最长 30 天，刷新时轮换 |
| 密码 | 数据库密码哈希 | 永不保存明文 |
| 用户资料/角色/账户 | CVM MariaDB `dandan_world` | 持久化 |

浏览器不使用 `localStorage` 或 `sessionStorage` 保存密码、refresh token 或验证码。关闭页面后再次打开，只要 refresh cookie 未过期且会话未撤销，页面会自动恢复；这满足“下次不用再输入账号密码”，同时不把密码写入浏览器。

## 验证码规则

- 只存 SHA-256 哈希，有效期 5 分钟，成功后单次消费。
- 最多输错 5 次；同一目标 60 秒内不能重发，并受小时级限流约束。
- 找回密码固定使用 `reset_password`，未知账号与已知账号返回一致响应。
- Mock provider 仅用于开发/烟测；生产需要腾讯云 SMS provider、已审核签名和模板。
- 注册时验证码不是联系方式的必填前置条件；提供有效 token 时才写入 `verifiedEmailAt` 或 `verifiedPhoneAt`。找回密码仍必须使用验证码。

## 权限与管理员

`User.role` 只有 `student` 和 `admin`。JWT 中携带角色，但所有管理操作仍必须由服务端认证钩子校验；前端隐藏按钮不是权限边界。管理员和普通用户共用会话恢复流程，差异只在服务端授权和页面展示。

## 当前缺口

- 最新 CVM 构建重启后，完整注册 -> 刷新 -> 重新打开 -> 退出 -> 找回密码流程需要重新烟测。
- 真实腾讯云 SMS 尚未配置；目前不能把 Mock 验证码当作生产短信已上线。
- 需要浏览器桌面和移动宽度回归，确认会话恢复后主站和盲盒 iframe 共享同一个 `/dd/api` Cookie。

- `server/src/auth/verification.ts`：验证码哈希、过期和消费规则。
- `server/prisma/schema.prisma`：`User`、`AuthSession`、`VerificationCode`。
- `backend-handoff-package/api-client.js`：Cookie 会话恢复和 API 客户端。
