# 资料反馈与权限重构

## 当前决定

- 个人资料开放二次编辑，昵称 30 天冷却，邮箱修改后变为未验证；MBTI、兴趣和技能与盲盒共用数据。
- “我的任务”整合为我发布的、我认领的、我的打听、我的反馈四个标签，按具体记录清除未读。
- 发布打听后直接进入“我的打听”，并修复/屏蔽 `Route GET` 原始技术错误。
- 采用 Prisma 规范化 RBAC + CASL，支持自定义角色、细粒度勾选权限、多角色并集、独立期限和即时失效。
- 两个固定管理员永久受保护，公开均只显示“管理员”；临时密码不写入本笔记，首次登录强制修改。
- 反馈升级为多轮时间线，支持待处理、处理中、待修改、已解决、已驳回；结束后 7 天内仅可重新处理一次。
- 图片附件仅支持 JPG/PNG/WebP，单张 5 MiB、每次 3 张，存入非公开 CVM 目录并通过鉴权 API 访问。
- 管理员不能任意浏览私聊，只能在用户举报后查看有限上下文，且必须审计。

## 当前状态

需求和设计已逐项确认并获批准。商城需求已改为复用同一套 RBAC，不再创建独立发布者授权表。下一步先完成共享 RBAC、资料、任务中心和反馈基础，再让商城接入权限键与资源范围；生产部署保持暂停，直到本地全量验证通过。

## 商城协作边界

- “蛋蛋校园-蛋蛋商城”是 Codex 任务工作目录，不是第二个 Git 仓库；唯一源码事实来源仍是 `D:\桌面文件\蛋蛋校园`。
- 商城发布者是预置 RBAC 角色，不新增 `ProductPublisherPermission`。
- 商城任务先负责商城专属领域 helper、测试和文档；共享 schema、鉴权服务、`app.ts`、`api-client.js` 与 `growth-school.html` 必须在明确交接后修改，避免并发覆盖。
- 固定管理员的临时密码仍只在部署时通过隐藏输入处理，不发送给另一任务、不写入协作文档。

## 经验

- 管理员期限不能只写进 JWT，必须在每次敏感请求中用服务端时间校验当前授权。
- 通用 RBAC 库只负责判定，固定管理员保护、期限、审计和反馈归属仍必须由业务数据库负责。
- 文件扩展名和浏览器 MIME 不可信，受保护附件需要内容签名检查、非公开存储和下载鉴权三层约束。
