# 部署与数据隔离

## 生产拓扑

```text
浏览器
  -> HTTPS dsxnb.com/dd/
  -> Nginx 静态文件 /var/www/dd
  -> /dd/api/* 反向代理到本机 Fastify 3310
  -> Prisma
  -> CVM 本机 MariaDB 127.0.0.1:3306 / dandan_world
```

- 健康地址：`https://dsxnb.com/dd/health`。
- Node 服务由 PM2 应用 `dandan-world` 守护。
- MariaDB 仅监听本机地址，不开放公网 3306。
- 前端 API 使用 `/dd` 前缀；本地预览可使用本地 API 地址。
- refresh Cookie 上游 Path 使用 `/api`，由 Nginx 重写为公开 `/dd/api`；这样认证和 `/dd/api/buddy-box/*` 都能携带同一 Cookie。

## 发布边界

蛋蛋校园的静态文件位于 `/var/www/dd`，API 只由本机服务提供。根路径 `https://dsxnb.com/` 的“航线”站点不属于本次发布范围；静态回滚和 Nginx 修改都必须避免覆盖根站配置。

## 数据隔离声明

本项目连接串只指向 CVM 上的 `dandan_world`。“航线”使用自己的 Supabase 项目；蛋蛋校园不读取其 URL、密钥、表、用户或迁移文件。生产发布包也不得包含“航线”源码或 Supabase 凭据。

## 环境变量边界

只记录变量名，不记录值：

- `DATABASE_URL`
- `JWT_SECRET`
- `REFRESH_COOKIE_ENABLED`
- `COOKIE_SECURE`
- `COOKIE_PATH`
- `VERIFICATION_PROVIDER`（当前生产值为 `disabled`）

这些值应留在 CVM `.env`、密钥管理或部署平台的 secret store。不得放入 Obsidian、聊天、压缩包、浏览器日志或版本库。

## 备份与回滚

现有脚本：

- `server/deploy/backup-dandan-world.sh`
- `server/deploy/verify-backup.sh`
- `docs/production-operations.md`

备份恢复必须先在独立临时数据库验证，不能直接覆盖生产库。回滚保留当前目录和上一版本目录，切换 PM2 版本后依次验证 `/dd/health`、受保护 API 的 401 和静态页面，再恢复流量。

## 上线前门槛

- 最新后端迁移和 Prisma Client 已在 CVM 部署。
- PM2 使用最新 `.env`，重启后仍能连接数据库。
- HTTPS 下 Cookie 带 Secure，API 只允许正式来源。
- 短信未配置且未启用；生产不会要求腾讯云 SMS 密钥。
- 备份、恢复和回滚演练有命令输出证据。
