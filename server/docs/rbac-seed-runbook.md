# RBAC 与固定管理员初始化 Runbook

## 适用边界

本流程只操作蛋蛋校园数据库 `dandan_world`。禁止连接、迁移或修改“航线”项目及其 Supabase。

## 上线前检查

1. 为 `dandan_world` 创建可恢复的完整备份，并在隔离环境验证备份可读取。
2. 确认服务器 `.env` 的 `DATABASE_URL` 完整包含应用账号、密码、地址和数据库名，行尾没有反斜杠。
3. 确认 `FEEDBACK_ATTACHMENT_ROOT` 指向站点公开目录之外，例如 `/var/lib/dandan-campus/private/feedback`。
4. 创建附件目录，并让后端服务账号拥有读写权限；目录建议 `0700`，文件由应用以 `0600` 创建。
5. 本机完成 `npm ci`、Prisma 生成、测试和构建。服务器只安装生产依赖、执行迁移和运行服务，不做前端构建。

## 数据库迁移与目录

逐条执行并逐条检查输出：

```bash
cd /root/dan-campus/server
npm run prisma:deploy
mkdir -p /var/lib/dandan-campus/private/feedback
chmod 700 /var/lib/dandan-campus/private/feedback
```

目录所有者必须是实际运行 PM2 后端的系统账号。不要把附件目录放在 Nginx `root`、`alias` 或其他静态文件目录下。

## 固定管理员初始化

1. 先在数据库只读查询中确认需要原地保留的现有管理员用户 ID。
2. 在服务器交互式终端执行：

```bash
cd /root/dan-campus/server
npm run admin:bootstrap
```

3. 输入现有管理员用户 ID。
4. 按提示分别隐藏输入并确认两个不同的临时密码。不要把密码放入命令参数、环境变量、Shell 历史、PM2 配置或聊天记录。
5. 工具会原地重命名第一个账号，幂等创建或更新第二个账号，设置受保护标识，撤销旧会话，恢复永久完整权限，并要求两个账号首次登录改密。
6. 工具若报告用户 ID 不存在或昵称冲突，应停止并核对账号，禁止通过删除用户来绕过冲突。

## 启动与验收

1. 重启后端一次，不要循环重启。
2. 查看 PM2 日志；若出现 MySQL 1045，先核对完整 `DATABASE_URL`，不要反复启动。
3. 检查健康接口返回 `{"status":"ok"}`。
4. 分别验证普通用户、限时管理员、固定管理员和已过期授权；JWT 中的旧 `role` 不能绕过数据库授权。
5. 验证固定管理员首次登录必须改密，改密后其他旧会话失效。
6. 验证附件只允许 JPG/PNG/WebP、每次最多三张、单张不超过 5 MiB，且公开静态路径无法直接访问附件。
7. PM2 显示 `online` 只代表进程存在，必须同时通过日志、健康接口和公开业务冒烟。

## 回滚

- 应用回滚：恢复上一版构建产物并重启一次；不要删除新增表或列。
- 数据回滚：仅在确认迁移导致不可接受故障时，按上线前备份恢复整个 `dandan_world`，不要手工删表。
- 附件回滚：保留私密附件目录，不要因应用回滚删除用户上传文件。
- 授权应急：固定管理员可以通过“用户与权限”撤销普通管理员授权；固定管理员自身保护不能通过公开 API 解除。
